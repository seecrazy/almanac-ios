# 宜历产品蓝图（历史设计恢复版）

状态：已恢复并归档（2026-11-01）  
来源：Codex 会话 `01a19205-ad9f-7731-a10f-fd3c511941d1`（2026-10-31 “设计 iPhone 日历应用方案”）  
用途：把尚未实现但已经讨论过的产品/交互/架构设计固化到仓库，防止会话切换后丢失。  
实现差距：见 [design-gap.md](design-gap.md)

## 1. 产品定位

**输入最快、信息最全的个人时间管理中枢。**

三个差异化支点：

1. 中文时间语义：农历、节气、黄历、法定调休。
2. 输入快：自然语言创建、未来自然语言问答。
3. 本地优先：日程事实来自 EventKit，App 层数据本地优先，云端只做私有同步。

对标产品：Apple Calendar、Google Calendar、Fantastical、国产万年历。  
品牌路线：不做成“大红大金的信息流万年历”，而做成安静、高信息密度的纸感时间工具。

## 2. 已恢复的核心设计域

### 2.1 日历核心能力

| 能力 | 设计要点 |
|---|---|
| 多视图 | 日 / 周 / 月 / 年 / 议程；手势切换 |
| 事件字段 | 标题、时间、地点、参与人、备注、URL、提醒 |
| 全天与跨天 | 顶部横条；跨天不拆成孤立日程 |
| 重复规则 | RFC 5545；无限重复惰性展开；EXDATE；单次/系列修改 |
| 多日历 | 颜色区分；显示/隐藏；订阅外部日历 |
| 时区 | 事件级时区；浮动时间；跨时区不漂移 |
| 搜索 | 标题、地点、备注、参与人全文搜索 |
| 邀请 | 接受 / 拒绝 / 暂定；邮件协议 |
| 冲突检测 | 创建/编辑时高亮重叠 |

当前 v0 只实现 EventKit 读取、手动创建、月/日详情；重复规则引擎只完成包级算法，未暴露到 UI。

| 能力 | 设计要点 |

### 2.3 中国日历层

#### 节假日

- 数据分三层：固定公历节日、农历推导节日、国务院年度休/班安排。
- 官方数据必须 JSON 化，每年 11–12 月更新次年数据。
- 当前仓库只有 `holiday-2026.json` sample，尚无官方数据管道。

#### 农历

- 1900–2100 农历换算、闰月、干支、生肖、月视图文本已实现。
- 未实现：农历节日高亮、二十四节气、农历生日、完整万年历面板。

#### 黄历 v1.1

设计分为两层：

1. 月视图轻量层：农历/节气/农历节日；优先级为法定节日 > 农历节日 > 节气 > 农历日期。
2. 日详情完整层：宜忌、干支、冲煞、建除十二神、胎神占方、彭祖百忌、纳音五行、财神/喜神/贵神方位。

技术路线：

- 干支、生肖、冲煞：纯公式。
- 农历与节气：本地算法。
- 宜忌等经验数据：查表 + 规则生成，禁止散落硬编码。
- 设置开关：默认关闭；开启后才显示完整面板。

### 2.4 生日 / 纪念日

目标能力：

- 阳历生日、农历生日、纪念日、忌日。
- 联系人生日批量导入。
- 年龄 / 周年显示。
- 多级提醒：提前 7 天、提前 1 天晚上、当天早上、自定义。
- 农历生日每年换算成当年公历日期；闰月规则必须显式处理。

数据归属：

- 不是普通 EventKit Event，而是 App 层 `Anniversary` / `Milestone` 模型。
- 可选择“同时写入系统日历”生成提醒代理，但源数据仍归 App 层。

### 2.5 里程碑与倒计时

模型：

```swift
struct Milestone {
    let title: String
    let targetDate: Date
    let category: Category
    let color: Color
    let countdownMode: Mode // 倒计时 / 正计时 / 自动
    let isAllDay: Bool      // 日期型 / 时刻型
}
```

展示策略：

| 场景 | 设计 |
|---|---|
| App 内 | `Text(timerInterval:)`；前台计时，后台停止 |
| 锁屏/桌面 Widget | 静态 timeline；24 小时内用系统 timer 渲染秒 |
| Live Activity / 灵动岛 | 冲刺场景；到零切换状态 |
| 通知 | 只做提前提醒；通知不能承诺秒级精度 |

精度模式：

- `auto` 默认：>7 天显示天；1–7 天显示天+小时；<24 小时显示时分秒。
- 日期型里程碑永远只显示天。
- 时刻型里程碑支持秒。

当前只有一个静态“高考”样卡，没有 `Milestone` 模型、列表页、编辑器、Widget 或 Live Activity。

### 2.6 智能闹钟与公司政策

平台限制：

- 第三方无法直接写入系统时钟 App。
- 可用 Time Sensitive Notification、≤30 秒自定义声音、专注模式穿透变体实现。
- 贪睡通过通知动作实现。

设计核心：

1. 基础重复：每天、工作日、休息日、自定义。
2. 调休感知：法定休日不响；补班日响。
3. 公司政策引擎：公司码、版本号、政策模板。
4. 常见模板：标准双休、单休、大小周、月末最后一个周六上班/休息、自定义日期。
5. 未来 60 天响铃预览：用户必须能提前看到哪天响。
6. 预计算 + 事件驱动重算：政策变化、节假日更新、时区变化、用户修改时重算。

### 2.7 数据迁移与同步

三条路径：

1. **CloudKit 私有库主路径**：设置、纪念日、订阅源、模板、日记等 App 层数据。
2. **系统备份兜底**：本地 SQLite / UserDefaults 随系统备份恢复，启动时做完整性校验。
3. **手动导出**：ICS 处理日历事件；加密 JSON 处理 App 层数据；AirDrop / 文件导入。

技术纪律：

- 离线优先：先写本地，后同步。
- 增量同步：只拉变更。
- 冲突策略：设置 last-write-wins；列表类数据按新增/删除合并。
- 导出永远是“无锁出口”。

当前尚未引入 GRDB、CloudKit、导出导入。

### 2.8 日记

定位：**日程是日子的骨架，日记是血肉。**

关键设计：

- 一天一篇 `DiaryEntry`。
- 自动生成当日日程骨架，用户删改后补几句感受。
- 心情、照片、语音、天气可选。
- 本地 SQLite，AES-256-GCM 加密；密钥放 Keychain。
- 可选独立密码 / Face ID。
- CloudKit 私有库同步加密字段。
- 全文搜索复用 FTS5 思路。

联动：

- 去年今天。
- 纪念日历史内容。
- 年度报告。
- 晚间轻提醒。

### 2.9 本地智能与增长

| 能力 | 设计 |
|---|---|
| 自然语言问答 | “下周三下午有空吗”“这个月和张三开了几次会”；本地 NLP + SQLite |
| 场景提醒 | 雨天带伞、通勤出发时间、连续会议插入休息 |
| 年度报告 | 本地统计，用户主动分享 |
| 倒计时分享卡 | 关键日传播 |
| 去年今天 | 每天最多一条，克制展示 |
| 公司日历市场 | 发薪日、司庆、班车、食堂、例会模板 |

明确不做：社交信息流、云端日程 AI 分析、全功能待办、广告。

### 2.11 打包与跨平台

打包路线：

1. 开发：USB 直装。
2. 自用/分发：TestFlight。
3. 发布流水线：fastlane + release checklist。

跨平台纪律：

- UI 原生。
- 算法纯逻辑：`LunarKit`、`RecurrenceEngine`、未来 `WorkdayResolver`、NLP 规则解释器。
- 数据 JSON 化。
- 同步抽象 `SyncProvider`，不绑死 CloudKit。
- ICS + JSON 导出兜底。
