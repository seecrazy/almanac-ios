# 自然语言日程输入设计 v1

状态：设计已接受；代码接入完成，GUI / 真机验收待完成  
架构依据：[ADR-008](../architecture/adr/ADR-008-natural-language-input.md) · [ADR-007](../architecture/adr/ADR-007-cross-platform.md)

视觉基线：[design-system.md](design-system.md)

## 1. 目标

- 月视图提供常驻快速输入框，用户输入一句话后能生成日程草稿。
- 解析结果必须打开现有 `AddEventView` 预填，用户确认后才保存到 EventKit。
- v1 覆盖高频中文表达：相对日期、显式日期、上午/下午时间、时间区间、时长、全天、基础重复规则、`@地点`、`#备注`。
- 解析完全离线；规则表可随 App 分发，不需要联网。

## 2. 非目标

- 不做云端 NLP、机器学习模型或服务器请求。
- 不自动保存、自动修改或自动删除任何 EventKit 事件。
- 不做一次解析生成多个日程。
- 不做英文完整语法解析；英文数字时间只作为显式 `HH:mm` 支持。
- 不做自然语言查询已有日程、批量导入或复杂重复规则。
- 不做智能提醒推断；提醒仍由表单默认值与用户选择决定。

## 3. 用户流程

```text
月视图输入一句话
  → 点击“解析”
  → NaturalInputParser 生成 QuickEventDraft + warnings
  → AddEventView 用草稿预填
  → 用户检查/修改标题、时间、重复、提醒和目标日历
  → 点击“保存日程”
  → EventStoreService.saveEvent(...)
```

快速输入框不清空未解析内容，直到草稿成功打开后清空；解析失败时保留原文并显示警告，方便修改重试。

## 4. 数据与状态模型

### `QuickEventDraft`

| 字段 | 说明 |
|---|---|
| `title` | 从原文剥离日期、时间、地点和备注标记后的剩余文本；缺失时使用“新日程” |
| `startDate` / `endDate` | 参考日内的普通时间段，或全天日历区间 |
| `isAllDay` | 命中“全天”时为 true，忽略时间表达 |
| `location` | `@会议室` 这类显式标记 |
| `notes` | `#重要` 这类显式标记 |
| `recurrence` | 不重复 / 每天 / 每周 / 每两周 / 每月 / 每年 |

### `NaturalParseResult`

| 字段 | 说明 |
|---|---|
| `draft` | 表单可直接消费的结构化草稿 |
| `warnings` | 用户可读解释，例如“未识别日期，已按今天处理” |

### 参考时间

解析器使用注入的 `Date`。`AddEventView` 当前可使用传入的初始日期作为参考；纯逻辑测试使用固定日期，保证不受真实时钟影响。

## 5. 关键解析规则

### 日期

| 输入示例 | 结果 |
|---|---|
| 今天 / 明天 / 后天 | 相对参考日偏移 |
| 大后天 | 相对参考日偏移 3 天 |
| 周三 / 礼拜三 | 参考日起向后查找最近星期三 |
| 下周三 / 下星期三 | 下一个自然周的同星期几 |
| 11月5日 / 11/5 / 2026-11-5 | 当年或指定年；过去显式年份保留用户意图 |
| 11月5号 | 与“日”等价 |

### 时间

| 输入示例 | 结果 |
|---|---|
| 09:30 / 9:30 | 24 小时制或普通小时分钟 |
| 9点 / 9点半 / 9点30分 | 本地时间表达 |
| 上午9点 / 下午3点 / 晚上8点 | 按时段修正 12 小时制 |
| 3点到5点 / 9:00-10:30 / 15时至16时 | 同日起止时间；结束不晚于开始时跨到次日 |
| 2小时 / 45分钟 | 没有结束时间时转换为结束时间 |

无日期时使用参考日。无时间且非全天时默认 09:00–10:00，并在警告中说明。

### 重复

| 输入示例 | 结果 |
|---|---|
| 每天 / 每日 | daily |
| 每周 / 每周一次 / 每周日 | weekly |
| 每两周 / 隔周 | biweekly |
| 每月 / 每年 | monthly / yearly |

v1 不解析“每月最后一个周五”“每两周的周一和周四”“工作日排除节假日”等复杂规则。这些文本若未被匹配，将保留在标题或进入警告，由表单兜底。

### 标记

- `@会议室` 提取地点。
- `#重要` 提取备注。
- 匹配到的日期、时间、地点、备注和重复 token 从标题中剥离。
- 标题多段空白压缩为单个空格；全空时使用“新日程”并警告用户补充。

## 6. 架构与包边界

- 新增 `Packages/NaturalInput` 本地 Swift Package。
- `NaturalInput` 只依赖 Foundation，不 import SwiftUI、EventKit 或 UI 框架。
- `App/Almanac` 负责输入框、调用解析器、把 `QuickEventDraft` 映射到现有 `AddEventView` 与 `EventRecurrenceDraft`。
- 中文基础词表、默认时段、标记前缀放入 `Resources/natural-input-rules.json`；解析器支持注入自定义规则，便于测试与未来扩展。
- `每周三` 这类“重复词 + 星期词”先剥离重复词并识别星期日期，避免普通标题中的“日”“周”被误判为日期。

## 7. 交互与视觉

- 月视图头部下方增加快速输入区；表单样式沿用 `card`、`ink`、`secondary`、`accent` token。
- 输入框占位文案：`明天下午3点到5点 开会 @会议室 #重要`。
- 主按钮文案：`解析`；键盘回车等价于点击解析。
- 解析有警告时仍打开表单，警告显示在表单顶部，颜色使用 `holidayRed`，不阻断用户继续编辑。
- 解析不出任何可写草稿时保留输入并提示“暂时不能识别，请用新建日程表单”。

## 8. 边界与错误处理

| 场景 | 行为 |
|---|---|
| 输入为空 / 全空白 | 不调用解析器，按钮禁用 |
| 未识别日期 | 使用参考日并产生警告 |
| 未识别时间 | 非全天使用 09:00–10:00 并产生警告 |
| 结束时间早于开始时间 | 视为跨天结束 |
| 全天与时间同时出现 | 全天优先，产生警告“已忽略时间” |
| 没有可写日历 | 既有 `AddEventView` 显示“没有可写入日历” |
| EventKit 保存失败 | 既有保存错误就地展示，解析器不吞错 |
| 复杂重复规则 | 不猜测；保持不重复或让用户在表单修改 |
