# 本地日历管理 v1.1

状态：代码已接入；GUI / 真机验收待完成（2026-11-05）
架构依据：[ADR-001](../architecture/adr/ADR-001-eventkit-as-source-of-truth.md)
关联设计：[多日历管理](calendar-management.md)

## 1. 目标

- 在日历筛选页创建本机 EventKit 日历。
- 重命名当前设备本地来源且允许修改的日历。
- 删除当前设备本地来源且允许修改的日历。
- 删除前明确提示会同时删除该日历中的日程。
- 管理失败时保留原状态并向用户展示错误。

## 2. 非目标

- 不管理 CalDAV / iCloud / Google 等远端日历元数据。
- 不修改日历颜色、共享成员、同步策略或订阅地址。
- 不迁移、合并或批量删除日历。
- 不把宜历筛选状态写入系统日历。

## 3. 用户流程

1. 月视图打开“日历筛选”。
2. 点击工具栏 `+`，输入名称并确认创建。
3. 对“本地 · 可写”日历点击 `⋯`：
   - 重命名：输入新名称并确认。
   - 删除：阅读确认弹窗后再次确认。
4. 操作完成后列表、可写日历选择和默认显示状态立即刷新。

## 4. 数据 / 状态模型

- `CalendarDisplayInfo` 增加本地来源标记，用于判断是否可管理。
- `CalendarManagementPolicy` 提供纯逻辑规则：
  - 名称 trim 后必须为 1...64 字符。
  - 名称不能仅包含空白。
  - 仅 `isLocal == true && allowsContentModifications == true` 的日历可重命名 / 删除。
- 创建必须使用 EventKit 的本地 source；找不到本地 source 时报错，不自动落到其他账号。

## 5. 关键交互

- 新建日历默认显示，不需要用户手动开启。
- 重命名保持显示 / 隐藏状态。
- 删除成功后从隐藏集合移除该 ID，避免留下失效记录。
- 删除确认文案明确“会删除该日历及其日程，且宜历内不能撤销”。

## 6. 边界与错误处理

| 场景 | 行为 |
|---|---|
| 未授权 / 权限被拒 | 不展示管理入口，提示系统权限问题 |
| 名称为空或超长 | 表单禁止提交并显示校验错误 |
| 无本地 source | 创建失败，不创建到远端账号 |
| 只读或远端日历 | 不提供重命名 / 删除操作 |
| EventKit 保存失败 | 展示系统错误，刷新当前列表 |
| 日历在操作间隙被删除 | 提示不存在，刷新列表 |
