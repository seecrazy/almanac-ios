# ADR-013: 节假日数据联网更新

状态：已接受（2026-11-10，同日实现）。

## 背景

节假日数据此前纯内置（[holiday-data-pipeline](../../design/holiday-data-pipeline.md)）：每年国务院办公厅 11 月前后发布次年安排后，需人工替换内置 JSON 并发版。用户指出：官方数据应能自动联网获取。

事实约束：国务院**没有官方 API**。社区数据集 [`NateScarlet/holiday-cn`](https://github.com/NateScarlet/holiday-cn)（MIT）是事实标准——每年通知发布后数日内更新，逐条对应官方通知原文（papers 字段带 gov.cn 链接），格式为年度 JSON（`days: [{name, date, isOffDay}]`）。

## 决策

1. **内置兜底 + 联网更新**：内置数据始终保留（离线可用 / 首启可用）；联网成功且校验通过的年度数据覆盖同年内置值，并持久化到 Application Support，下次启动直接生效。
2. **信任策略（零信任解析）**：远程数据仅经"结构校验 + 业务校验"后才可采用——
   - 年份 ∈ {当前年, 当前年+1}；日期格式合法、去重、必须落在声称年份内；
   - 休日 ≥ 5 天、总天数 ≤ 80、名称非空；解析失败 / 任一校验失败 → 丢弃该年，静默回退内置；
   - 仅 HTTPS（GitHub raw 主源，jsdelivr 镜像备源），10 秒超时，无自动重试风暴；失败不打扰用户（设置页可见状态）。
3. **纯逻辑下沉**：`HolidayData` 包内实现远程数据集模型 + 校验 + 转换 + 与内置数据的合并（零网络依赖，URLSession 留在 App 层 `HolidayDataCoordinator`），维持 ADR-007。
4. **数据源标注**：远程数据标 `official`，note 注明「国务院办公厅通知（holiday-cn 数据集）」；设置页展示上次检查时间与手动「检查更新」。
5. **自动检查策略**：App 激活时检查，24 小时内最多一次；用户可手动强制。
6. 顺带结论：2027 官方通知已于 2026-11 发布，**内置 2027 数据同步替换为官方版**（离线亦有官方数据）。

## 后果

- 正面：次年数据零发版自动就位；用户可手动刷新；离线不降级。
- 负面：引入对第三方数据集的正确性信任（校验规则只能防结构性错误，无法防内容转录错误——接受，因数据集带官方原文链接可溯源）；App 首次出现网络行为（仅两个 GET，无任何隐私数据）。
- 后续：数据集若失效，备源 + 内置兜底保证可用；如官方提供 API 可替换数据源而不动架构。

## 验收

- [x] 内置 2027 替换为官方数据（manifest + 年度 JSON，含通知链接）
- [x] 设置页：数据来源说明 / 上次检查 / 手动检查 + 状态
