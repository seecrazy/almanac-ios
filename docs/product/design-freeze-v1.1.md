## 1. 开发流程

| 阶段 | 动作 |
|---|---|
| 开发前 | 从本表选择 Task ID，读取关联设计；确认验收范围 |
| 无设计变更 | 直接实现；提交说明写 `Design Ref: D-xxx` |
| 发现设计缺口 | 先更新对应设计文档，再继续实现 |
| 明确变更 | 在设计文档记录旧方案、新方案、原因；更新本表状态 |
| 收尾 | 更新 roadmap / HANDOFF / README / design-gap |

本基线覆盖到 v1.1；v1.2+ 仍只保留方向，不在本文件中承诺实现细节。

## 3. 全局约束

1. EventKit 是系统日历事件唯一事实源；App 层数据只存本地。
2. 纯逻辑放入 Swift Package，不依赖 SwiftUI / EventKit / UI 框架。
3. 规则表使用 JSON；生成器和解析器必须可测试。
4. 没有官方数据时必须显示 `sample / estimated` 来源，不能伪装成官方。
5. 平台能力没有 extension target 前，不宣称已支持 Widget / Live Activity。
6. 权限拒绝、无数据、规则不支持、日期越界必须有明确用户反馈。

## 4. 收尾口径

| 状态 | 含义 |
|---|---|
| 设计已冻结 | 有目标、模型、流程、边界、验收清单 |
| 代码已接入 | 编译 / 测试通过，但未完成 GUI / 真机验收 |
| 已验收 | 完成设计文档验收清单中的 GUI / 真机项 |
| 设计变更 | 修改了字段、流程、边界或非目标，需要先更新设计 |
